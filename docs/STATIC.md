# Frontend & Static Assets

This document covers the frontend architecture, focusing on the complex JavaScript logic driving the multi-track audio player and liturgical navigation.

## Structure

- `static/css/`: Layout and liturgical color styling.
- `static/js/`: Modular ES6 scripts (no framework).
- `static/icons/`: Site icons and social preview assets.
- `static/vendor/`: Manually vendored third-party libraries. See `docs/VENDORED_ASSETS.md`.

---

## JavaScript Architecture

The app uses vanilla JS to manage high-performance audio, search autocomplete, liturgical navigation, and PDF rendering.

Inline event handlers are intentionally avoided. Templates expose behavior through `data-*` attributes, and static JS attaches delegated listeners. This keeps production CSP strict enough to remove `script-src 'unsafe-inline'`.

### `audio-engine/` (Multi-track Sync)
High-precision SATB player using the **Web Audio API** and **HTML5 Audio**, modularized for clarity.
- **context.js**: Manages the `AudioContext` lifecycle and global hardware settings.
- **player-core.js**: `SyncedTrackPlayer` coordinates multiple voice tracks, per-track gain, solo/mute, progress, seeking, and Safari-specific playback paths.
- **manager.js**: `WebAudioPlayerManager` handles multiple player instances.
- **Mixer**: Each track (Soprano, Alto, Tenor, Basse, Instrument) is routed through independent `GainNode` objects for live volume/mute control.

Browser-specific behavior:
- Desktop/non-Safari uses media elements routed through `MediaElementAudioSourceNode`, with periodic drift correction.
- Safari at normal speed uses decoded `AudioBufferSourceNode` playback for tighter synchronized starts.
- Apple/Safari speed changes use three visible tempo buttons backed by server-generated stem variants at `0.5x`, `1.0x`, and `1.5x`; the browser still plays them at `1.0x` through the mixer.
- Non-Safari keeps the continuous speed slider, but avoids unnecessary buffer decoding and uses conservative mix headroom to reduce audible artifacts.

### `audio-player/` (UI & Orchestration)
Manages player state and user interactions.
- **ui.js**: DOM manipulation for player controls, progress bars, and track mixing.
- **polling.js**: Listens for backend synthesis completion when MXL files are being processed.
- **controls.js**: The "bridge" that connects the UI to the playback engine.
- **initializer.js**: Automates player setup across the site using data attributes.

Dynamic controls are built with DOM APIs, not raw `innerHTML`, so voice labels and media URLs do not become script injection surfaces.

### `pdf-viewer.js` & `pdf-auto-render.js`
Renders partitions using **PDF.js**.
- **Canvas Rendering**: Draws PDF pages directly to a `<canvas>` element.
- **Auto-render**: Automatically opens the viewer on detail pages.
- **Fallback**: PDF templates include a direct open/download path for users or browsers where canvas rendering is unavailable.

### `calendar.js` (Liturgical Navigation)
Drives the AJAX-based date switching.
It formats local dates directly instead of relying on UTC serialization, preserving Paris-day behavior around midnight.

## CSS & Style
- `calendar.css`: Custom styling for date pickers.
- `main.css`: Single entry point importing modular components from `css/components/`:
  - `layout.css`: Global styles and backgrounds.
  - `audio-player.css`: Styles for the SATB mixer.
  - `pdf-viewer.css`: Controls and canvas layout.
  - `search.css`: Autocomplete dropdown styles.
  - `liturgy.css`: Sticky headers and liturgical spacing.

## Security Notes

- CSP is generated by Django in `psalm_project/security.py`; Nginx should not add a second CSP header.
- Executable inline scripts must include `nonce="{{ request.csp_nonce }}"`.
- New JS should prefer delegated listeners, `textContent`, `setAttribute`, and explicit element construction.
- Avoid loading all audio tracks eagerly. Current player code performs one delayed background preload per session to reduce data and CPU cost.
- Static JavaScript syntax is checked in CI with `npm run js:check`; Node is a development/CI tool, not a production runtime dependency.
